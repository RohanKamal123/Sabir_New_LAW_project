01 — The problem

The work is repetitive, and the mistakes are expensive.

Four tasks repeat every single working week. Each is easy to do badly and costly to get wrong.

Task 1

Check the cause list

Every evening the Court publishes the roster of tomorrow's hearings. The barrister must find their own matters across ~60 benches — at 9pm, the night before.

Task 2

Track the case

Old matters move slowly. A result — an order, an adjournment, a judgment — can appear on a case you'd stopped watching. Someone has to re-check the history.

Task 3

Watch the deadline

Filing deadlines are set by law, not by the judge. Miss one and the client's cause of action can be barred entirely — the most expensive mistake in practice.

Task 4

Draft correctly

A petition has a fixed, conventional shape. Drafting is slow, and a wrong citation or a wrong section can sink a matter you'll only regret later.

The Court offers no API. The list is plain HTML, published the evening before. The statute text is free. Nothing exists to tie it all together — until now.

02 — The product

One desk, four doors in.

One set of services. Four surfaces — a Telegram bot for the phone, a web UI for the desk, a command-line for scheduled jobs, and an API. They can never disagree, because they are the same software.

Web UI

Your desk

Today, the cause list, your files, the diary, statutes, the limitation calculator, drafting. Designed to print like the documents you already read.

Telegram

Your pocket

/today, /diary, /case First Appeal 226 2013, /note, /time. The alerts arrive here at 9pm — in the app you already have open.

CLI

The scheduled sweep

One cron job each evening reads the whole published list, matches your matters, and sends one grouped message. Idempotent — nothing is ever sent twice.

API

The wiring

A clean JSON interface over the same logic, so anything else you build never drifts from the rest.

Feature 02

Case-status tracker

Tracks a case's full hearing history from the Court's own pages and flags only the changes that matter: a new listing, a result filled in, or a result amended.

What it saves youRe-checking a history by hand every week, on cases that may not have moved in months. It tells you when something actually happened.

Feature 03

Statute lookup

Search the official Bangladesh Code for the exact text of a section — verbatim, never summarised, with the source URL attached.

What it saves youThe "which act, which section, which words" guesswork. What a judge reads is the exact statutory wording — this hands it to you.

Feature 04

Template-based drafting

Pick a document — writ petition, leave to appeal, stay application, condonation application. Supply parties, facts, grounds and prayers. The template owns the structure; the AI writes only the narrative from the facts you gave.

04 — Why you can trust it

Built to be honest, not to impress.

The credibility of practice software rests on one thing: the barrister believing the red things when they appear. So the product is designed around what it refuses to do.

Statute text is verbatim, not generated

Results are exact spans from the official Bangladesh Code, with the source URL. Zero hallucination risk by design.

Rules are encoded, not guessed

Limitation periods and filing deadlines are rule-based date arithmetic — sections 4, 5 and 12 applied as exact law, not as model memory.

The working is shown

A limitation figure you cannot audit is a figure you cannot file on. Every step, every citation, every exclusion is laid out.

It prints like your documents

Designed around the printed cause list and the law report — and it prints correctly. You can take it to court.

Where it deliberately says no

It never answers with a Bangladeshi judgment from memory — reporters are paywalled, and even the big global tools invent citations 17–33% of the time. It refuses unverified limitation articles until a lawyer checks them. It refuses to cite any authority you didn't supply. Every refusal is a trust feature, not a missing one.

06 — What's next

Built now, and honest about the road.

The full desk is built and tested. Two directions follow, and both are gated on correctness, not ambition.

Now · Tier 1

Depth for daily use

More limitation articles verified with lawyers, richer diary automation, and the pieces that convert daily users into paying ones.

Later · Tier 2

Grounded case-law research

A real, checkable corpus of judgments — RAG with citation accuracy as the core problem. Not shipped until the citations are right. Shipping it wrong costs more trust than not having it.

The absence of case-law answers is deliberate. It is the difference between a tool that helps and a tool that misleads — and it is why the refusal earns trust.

07 — The ask

Put it on your desk for a week.

Try it on your real cause list.

Register yourself, tell it what to watch, and run the sweep the evening the list drops. It will send you one message with everything that's yours tomorrow.

Then open a real file, run a real deadline, and draft a real first draft. Where it is wrong — tell us. That is the product's whole point: every place it could be confidently wrong is marked, and the corrections are how it gets better.

No marketing. No client-matching. No public listing of barristers. This is inward-facing practice software, built for one barrister's own desk — yours.
